## 累计改动

1. **NovelAI / GPT 多组连接**（`069e57d`）：每家最多 50 组，保存名称、地址和密钥；GPT 模型、NovelAI 的 Opus 假设各组独立。旧配置自动迁移，新建不继承旧密钥。普通设置只存连接信息，密钥继续走本机 KeyStore；加密备份可恢复全部组。删除/清除仅影响选中的组。生成或排队时阻止换连接，切换后旧订阅查询不能覆盖新账号。
2. **ComfyUI 多工作流**（`b30a4a1`）：最多 20 套（含保留的默认套），导入后自动选中；可命名、切换、删除，同名导入另存并加编号。旧自定义流程保留为「原有工作流」。每套保留原始 API JSON 内的多个 LoRA 及其强度、节点连接，分别记住模型、VAE、采样器、调度器、步数、CFG、尺寸和 CLIP Skip；地址/画风仍共用。参数沿用占位符替换，文件内写死的参数保持原值。移除 JSON 粘贴框和粘贴保存按钮，保留文件导入和从酒馆导入。
3. **原生 LoRA 编辑与方案**：新增独立编辑面板，读取 ComfyUI 自带列表，支持手填、替换、多条叠加、强度、启停和移除；保存当前或另存，保留原始工作流可恢复。操作仅针对原生 LoraLoader / LoraLoaderModelOnly 及明确识别的接入位置，未知节点保留。关闭面板丢弃工作流草稿，读取列表不会抹掉输入，关闭后取消请求。ComfyUI 队列改为捕获每次提交的配置，允许为下一张图改方案，已排队任务不受影响；生图引擎/账号切换保护仍保留。
4. **绘画 App 集中方案与草稿**（`8c89172`）：方案选择、LoRA、模型参数、导入/改名/删除/保存/另存集中到绘画 App；引擎只留连接设置。复用手机组件和配色，说明放入小 i，列表设置折叠。新增会话草稿，离开 App 保留、刷新页面丢弃；试画使用草稿，自动出图仍使用已保存方案。保存失败或陈旧保存保留草稿；默认只能另存。参数按实际占位符显示，已排队请求仍保留提交配置。
5. **LoRA 卡片栏**（`b8b53f7`）：LoRA 移到与 NovelAI Vibe 对应的第四栏，复用卡片网格；出图方案的选择、保存和管理整块移入 LoRA 栏，绘图首页不再额外插入方案卡片；去掉重复方案名称。当前方案和可用文件分开展示。点卡片打开单条详情，可换文件、调强度、启停或移出；添加后直接应用到绘画草稿。列表支持搜索，切连接清缓存和旧返回，关闭取消请求。删除采用弹层内二次点击，帮助仍在小 i。原生接口仅返回文件名，使用统一图标。
6. **绘图交互对齐**（`d6eed3b`）：删除 ComfyUI 专属空画布缩小规则，恢复与另两引擎共用尺寸；删除方案内重复参数跳转。LoRA 新增/编辑的模型和文字强度使用共用 slider/meter-label，整行滑杆实时读数；常用范围 -2～2，导入值超出时扩展范围，未拖动保留原值精度。读取/刷新直接放到可用目录标题旁，手动添加在目录下；恢复操作收进更多操作。接入位置不支持 CLIP 时隐藏该项，未选位置/文件时禁用添加。
7. **近期绘图代码整理**（本轮）：删除已无界面入口的旧批量 LoRA 面板及其保存/另存/恢复分支、专属样式和导入；编辑器统一应用到绘画草稿，方案持久保存与恢复沿用当前入口。合并重复 input/change 处理，移除未使用的 `comfyPlans` 参数。现有卡片交互、保存取消和布局不变。
8. **说明与测试**：更新使用说明，纠正旧文档里 NovelAI 只能保存一个密钥的描述。没有改发布版本号或安装服务器插件。

## 重点检查

- 旧设置迁移能否保留地址、密钥、工作流和参数；保存失败时是否保持原状态。
- 生图连接的密钥隔离、导出脱敏、删除与加密恢复；旧订阅回包和正在输入的草稿。
- ComfyUI 切换时当前字段和保存列表是否一致；默认流程是否保留；含多个 LoRA 的请求是否原样连接。
- 出图期间和后续排队任务的配置保护；任务全部完成后能否立即切换。
- 原生 LoRA 添加/移除时是否正确处理 MODEL / CLIP 两路、保留 VAE 与未知节点；停用后请求副本是否正确跳过，保存原件是否仍能恢复。
- 列表读取的代理/直连区分、错误反馈、陈旧返回隔离、表单草稿与关闭取消；保存时防止覆盖别处修改过的方案。
- 文件校验失败、超限、删除取消、重载和设置备份恢复。

## 给 Claude 的前端交接

- `ui/comfy-lora-panel.js` 负责 LoRA 第四栏、卡片目录、搜索和请求生命周期；`ui/comfy-loras.js` 的 `nodeId` / `addFile` 选项打开单条详情，`catalog` 提供已读取的文件候选。列表只提供文件名，不提供封面，卡片统一图标不冒充模型预览。
- `ui/comfy-plans.js` 负责绘画页方案卡片和管理弹层；`ui/comfy-loras.js` 始终应用到绘画草稿，不直接落盘，不再需要 `draft` 模式参数。恢复入口在 `comfy-lora-panel.js` 的更多操作。`ui/draw.js` 负责参数/提示词/出图，`phone.css` 沿用现有颜色变量。
- 功能接口：`getComfyDraft()` 返回 `value/base/dirty/conflict/controls/loras/missing`；`updateComfyDraft({params, workflow, disabledLoras}, expected?)` 原子更新草稿；`resetComfyDraft()` 放弃修改并跟随当前已保存方案；`saveComfyDraft({name,copy})` 保存/另存，失败不清草稿。`drawQuote(params,true)` 和 `generateImage({...input,useComfyDraft:true})` 仅用于手动试画。旧接口继续兼容。
- `controls` 是工作流占位符支持的字段；未出现的参数不展示无效控件。不保证识别所有自定义节点、实际模型兼容性或工作流写死的尺寸。LoRA 节点连接仍由纯函数处理，UI 只负责收集表单。
- 滑杆原值通过 `data-lora-original` 保存，首次 input/change 后才读取滑杆数值，避免浏览器按步长修正导入小数；不要删掉这层保护。LoRA 滑杆现在为常用范围 -2～2，随导入原值扩展；未新增任意精确数值输入，后端 -100～100 校验仍保留。
- 后续可细修卡片密度、按钮层级、文件选择/强度控件和窄屏视觉；保持草稿与保存的区别、失败不丢修改、帮助不关闭编辑弹层、自动配图不被临时修改干扰。手机现有弹层只能同时打开一个，确认操作需保留当前草稿。
